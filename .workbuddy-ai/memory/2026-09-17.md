# 17.09.2026 — пропало поле ввода в чате (найдено две причины)

## Что видел пользователь
После запуска через Electron окно открывалось, но **поле ввода ответа для
нейросети отсутствовало** — только верхняя панель.

## Причина 1: устаревшая сборка интерфейса
`apps/web/dist/` был собран **13.09 09:34**, хотя исходники клиента правились
до 17.09. В сборке физически **не было** новых файлов:
- `installScreenCapture` — 0 совпадений,
- весь голосовой модуль (`voice/`, `stt-engine`, `voice-providers`) — 0.

При этом клиентские бандлы `packages/client/*/lib/client.js` были свежие
(17.09 04:01). То есть **пересобиралась библиотека, но не фронтенд-страница**.

Лечение: пересобрать `apps/web`. Сборка старым способом
(`pnpm run build:web`) **не проходит** — `pnpm` сам запускает `install` и
падает на защите удаления. Рабочий обход:

```
cd apps/web && ../../node_modules/.bin/vite build --outDir dist-new --emptyOutDir
```

Затем новый `dist-new` заменяет `dist` (старый сохранён в
`apps/web/dist.backup-20260917`, 13 МБ).

## Причина 2 (главная): защита WorkBuddy ломает замок приложения
Симптом в логе при старте:

```
dsh: plugin tree failed to load: failed to apply loader entry connection
(@deepseek-ai/dsh-client-connection):
[safe-delete][SAFE_DELETE_BULK_CONFIRM_REQUIRED] {"count":1117,"threshold":50,
"targets":["C:\\Users\\Dedy_Sher\\.dsh\\.credentials.yaml.lock"],"targetCount":1}
```

Механизм:
1. `withFileLock` (`packages/util/atomic-write/src/index.ts`, строка ~181)
   снимает свой замок через `rm(lockPath, { force: true })`.
2. В окружении, унаследованном от WorkBuddy, `fs.rm` **подменён** защитным
   модулем: `NODE_OPTIONS=--require=".../node-language-shim.cjs"`, плюс
   `CODEBUDDY_SAFE_DELETE_*`. Он считает удаления и после порога 50 отказывает.
3. Снять замок не удаётся → строку `connection` не применить → **дерево
   плагинов падает целиком** → интерфейс не монтируется.

Важно: приложение тут **не виновато**. Оно удаляет один свой файл; защита
видит суммарный счётчик по всей сессии и блокирует.

По коду (`atomic-write`): чужой/брошенный замок **намеренно не удаляется** —
«orphan recovery is an operator action». Поэтому самолечения нет.

Лечение: запускать приложение **без защитных переменных** WorkBuddy.

## 17.09.2026 (доп. 2) — Настройки кнопки «Улучшить текст» в своём пункте меню (вариант А)

**Решение пользователя: «вариант А»** — переиспользовать существующую машинерию
провайдеров, а не писать вторую форму.

**Ключевой вывод, который надо помнить.** Требование «добавлять провайдера прямо
из этого пункта» **уже выполнено без дублирования**: обе страницы читают один
реестр (`session/modelCatalog`) и пишут в одни и те же пространства
(`llm-deepseek` / `llm-pi-ai`). Значит, переиспользование достигнуто **общим швом
данных, а не копированием формы**: провайдер, добавленный на «Моделях», сразу
виден в списке новой страницы. Вторая форма здесь была бы вредна — две страницы
разошлись бы в понимании «что такое провайдер».

**Архитектура (два слоя выбора маршрута).** Своё пространство настроек
`draft-restructure` — **не** `agent-default-model`. Порядок чтения: выбранное
кнопкой → иначе модель по умолчанию для Агента. Выбор читается **в момент
вызова**, поэтому правка действует без перезапуска и регистрации пересобирать не
нужно.

**Правило «оба или ни один».** Половинчатая пара (`provider` без `model`)
отвергается и при запуске, и при сохранении (`installSection(..., { validate })`).
Причина: смена провайдера оставляет старое имя модели, и такая пара адресовала бы
несуществующий маршрут. Смена провайдера в форме очищает модель — по той же
причине. **Не ослаблять это правило «на всякий случай»:** тихая подстановка
умолчания спрячет ошибку формы за работоспособным поведением.

**`draftRestructureRoute`.** Провайдер, ушедший из сборки между записью и
вызовом, **не приводит к падению** — идёт откат на модель по умолчанию. Без
проверки обслуживаемости ошибка всплыла бы глубоко внутри потока словами про
«неизвестного провайдера», а не про настройку, которая это вызвала.
`ReasoningEffortId` — **значение** (не `import type`), иначе `TS1361`.

**Ловушка: пустые ссылки `ln -sfn` на Windows.** `ln -sfn` создаёт **пустой
каталог** вместо ссылки: путь «существует», а модуль не находится (`TS2307`).
Рабочий способ — `New-Item -ItemType Junction` **через инструмент PowerShell**
(внутри него и `mklink /J` проходит; а `cmd //c "mklink ..."` из bash открывает
интерактивную сессию и молча ничего не делает). Проверять не факт существования
пути, а **содержимое**: `ls node_modules/@deepseek-ai/<пакет>/` должен показать
`src`, `lib`, `package.json`.

**Ловушка: без локального `tsdown.config.ts` пакет молча не собирается.**
Корневой конфиг берёт `packages/*/*`, но клиентскую половину (`lib/client.js`)
выпускает только пакет со **своим** конфигом:
`export default clientBundle('<имя пакета>', ['lib/types/index.js'])`. Без него
`lib/index.js` есть, а `lib/client.js` — нет, и в интерфейсе ничего не появляется.

## 18.09.2026 — почему окно говорило «Backend failed to start in time»

**Причина.** Новый пакет хоста `packages/core/draft-restructure-model/` был
собран, зарегистрирован в `cordis.patch.yml` — но у него **не было своего
`node_modules`**. Дерево плагинов при старте пытается импортировать его и
спотыкается: `Cannot find package '@deepseek-ai/cordis' imported from
.../draft-restructure-model/lib/index.js`. Одна нерабочая запись роняет
**всё дерево целиком**, поэтому сервер не печатает строку готовности, а окно
через таймаут показывает ту самую фразу.

**Почему молча.** `electron/main.js` ничего не диагностирует: он ждёт строку
`dsh web: http://127.0.0.1:<порт>/?token=...` и по таймауту выдаёт общий текст.
Диагноз ставится только ручным запуском бэкенда (команда — в `MEMORY.md`).

**Как исправлено.** Созданы junction-ссылки на `cordis`, `schemastery`,
`dsh-llm`, `dsh-settings` (по образцу соседа `agent-default-model`).
`ln -sfn` не подошёл: он создаёт пустой каталог, и `tsc` даёт `TS2307`.

**Проверено после починки:** бэкенд печатает строку готовности; страница
перечисляет `@deepseek-ai/dsh-client-ui-settings-improve-text`; сборка по
адресу из `__DSH_BOOT__.entries[].url` отдаётся 200 (28847 байт) и содержит
«Улучшить текст»; приложение запущено, его бэкенд отвечает 401 без токена.

**Важно на будущее:** любой новый пакет (и хоста, и клиента) обязан получить
junction-ссылки на свои зависимости до запуска приложения. `pnpm install`
здесь недоступен, поэтому шаг делается руками.
