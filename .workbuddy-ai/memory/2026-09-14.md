## Проверка вживую БЕЗ окна и браузера: команда жива (03:55) ⭐

Пользователь сказал «продолжай» — вместо ожидания перезапуска **проверил сам**,
вызвав серверную команду напрямую. Приём стоит помнить, он даёт сквозную проверку
без интерфейса:

1. Поднять сервер: `node apps/cli/lib/bin.js web --port <свободный> --no-open`
   (в фоне; первая строка вывода — `dsh web: http://127.0.0.1:<port>/?token=…`).
2. Зайти по адресу с токеном (`GET /?token=…`) → ответ `303` + cookie
   (`set-cookie`). Это и есть вход в приложение.
3. Отправить команду обычным запросом — тот же путь, что у интерфейса:
   `POST http://127.0.0.1:<port>/api/<область>/<команда>`, заголовки
   `content-type: application/json` + `cookie`, тело:

```json
{"type":"client-request","rpcId":"<uuid>","method":"<область>/<команда>",
 "payload":{"args":{"request":{ …аргументы… }}}}
```

Ответ: `{"type":"server-response","rpcId":…,"result":{"ok":true,"value":…}}`
или `{"ok":false,"error":{"code":…,"message":…,"details":{}}}`.

**Грабли формы запроса (получены перебором, каждый раз новая ошибка):**
- `payload:{text:…}` → `Remote payload must contain exactly one plain-object args field`
- `payload:{args:{text:…}}` → `args fields do not match the descriptor: missing "request"; unexpected "text"`
- правильно: **`payload:{args:{request:{…}}}`** — `request` это имя первого
  параметра метода, `signal` в теле не передаётся.

**Протокол (из кода):** `packages/client/connection/src/client/rpc.ts` — POST на
`<origin><channel>/<endpoint>`; `api-path.ts` — префикс `/api`; вход — токен в
адресе корневой страницы, дальше cookie (`browser-auth.ts`). **Использовать
`node:http`, а не `fetch`** (в песочнице экспортированы HTTP_PROXY/HTTPS_PROXY →
fetch к loopback уходит через прокси).

  локальном порту и отдавать `http://127.0.0.1:<порт>`. Правки: `electron/v2ray.js`,
  `electron/port-selector.html`, `electron/tests/v2ray.test.js`.

**Ключевой приём на будущее:** сравнивая «у меня работает, у пользователя нет» —

## Вечер 14.09 — нечитаемая ошибка туннеля (жалоба пользователя)

Пользователь прислал из запущенного приложения:
`Error invoking remote method 'v2ray-start': Error: V2Ray не найден. Поместите v2ray.exe в installer/resources/v2ray`

**Что это значит:** (а) раздел «Сеть» **дошёл до интерфейса и нажимается** — задача
выполнена; (б) движка `v2ray.exe` в проекте правда нет — папка
`installer/resources/v2ray/` содержит только `README.txt`; (в) на экран просачивались
«внутренности» Electron — это и есть настоящая жалоба.

**Исправлено:**
- `packages/client/ui-settings-network/src/client/v2ray-bridge.ts` — причина берётся
  «по свойству» (`error.message`), обёртка срезается одним закреплённым выражением:
  `/^(?:[A-Za-z]*Error:/s*)?(?:Error invoking remote method '[^']*':\s*)?(?:[A-Za-z]*Error:/s*)?/`.
- `electron/port-selector.html` — то же самое функцией `readableError(error)`
  (7 мест) + `warnIfCoreMissing()`: предупреждает **при открытии окна** и при
  включении переключателя, а не после нажатия «Подключить».
- `NetworkSection.tsx` — `binaryReady = status?.binaryAvailable !== false`;
  кнопка «Подключить» **выключена**, если движка нет; `connect()` возвращает
  понятный текст вместо похода в оболочку.

**Ловушка (важно):** ошибка, пришедшая через мост из другой части приложения, —
**не** экземпляр `Error` этой части. `instanceof Error` даёт ложь, обёртка не
срезается, и `Error invoking remote method …` снова уезжает на экран. И `oxlint`
правила `no-base-to-string` не даст написать `String(error)` для постороннего
объекта — и правильно.
